## Hard Architecture Clarifications

1. NexusNet is not merely a tool router, chatbot wrapper, or static orchestration shell. The chats frame it as an artificial womb and gestation system for a birthed child MoE.
2. The birthed model must retain all NexusNet functions internally: memory, routing, tool governance, sandboxing, evaluation, promotion, rollback, self-research, skill generation, teacher review, and creator-facing observability.
3. The child MoE must not become an opaque sealed model. Creator-grade deep-brain observability is a core requirement, including introspection into routing, memory, expert activation, promotion evidence, and self-improvement traces.
4. Assimilation targets are usually sidecars, adapters, foundries, teacher resources, runtime optimizers, or evaluation patterns. They are not default core replacements unless they pass the full NexusNet promotion path.
5. Source-boundary discipline is mandatory. The Manifest chat corrected an earlier overreach: transcript evidence and repository evidence must stay separate unless both have been inspected and attributed.

## Priority Waves

### Wave 0 - Canon and Governance Locks

These are not optional implementation features. They shape every later assimilation decision.

- Birth doctrine: NexusNet gestates a child MoE that internalizes the whole NexusNet functional stack.
- Creator observability: no target can be promoted if it reduces introspection, auditability, rollback, or deep-brain visibility.
- Ledger discipline: chat-derived targets remain `candidate`, `research_only`, `code_backed_candidate`, or `locked_clarification` until ledgered and gated.
- Source discipline: external claims require source-class tags such as transcript-only, repo-inspected, paper-inspected, benchmark-inspected, or code-backed.

## Target Architecture Map

### SkillOps and Self-Improvement

Create a sidecar-style SkillOps layer that lets every AO, expert, orchestrator, and child module propose, test, register, refine, retire, or share skills. The sidecar should not own NexusNet's self-improvement loop; it should provide reusable infrastructure consumed by hive-wide neuroplasticity.

Candidate surfaces:

- `nexusnet/sidecars/evolutionary_skills/`
- `nexusnet/skills/registry.py`
- `nexusnet/skills/sandbox_runner.py`
- `nexusnet/skills/retention_policy.py`
- Control Panel replay cards for skill source, tests, owner node, promotion state, and rollback state.

Required gates:

- Skills are package-like artifacts with instructions, scripts/resources, tests, source refs, owner, scope, and rollback metadata.
- No skill can register without sandbox success and provenance.
- Skills need retention review and retirement paths, not only creation.
- Reusable Hermes-style reflection patterns can inform the design, but source code import remains blocked until source/license/security review.

### Scratch Apprentice Foundry

Assimilate scratch-training material as a foundry, not a brain replacement. The goal is a reproducible local lane for tiny apprentice models trained under NexusNet teacher supervision.

Candidate surfaces:

- `nexusnet/foundry/scratch_apprentice/`
- `nexusnet/foundry/curriculum.py`
- `nexusnet/foundry/apprentice_eval.py`
- `nexusnet/foundry/distillation_trace.py`

Required gates:

- Teacher-generated curriculum artifacts.
- Tiny-model training run proof on local or declared hardware.
- Quantization-aware or low-resource training experiments isolated from production routing.
- Evaluation scorecard against baseline, teacher, and task-family expectations.
- Promotion can only create shadow candidates unless governance approves further movement.

### Inference Economy and Runtime Acceleration

Manifest, MiniCPM5-1B-GGUF, EAGLE 3.1, and OSCAR form a coherent runtime economy lane.

Recommended split:

- Manifest pattern: route across available models by task difficulty, cost, latency, accuracy, privacy, and context needs.
- MiniCPM5-1B-GGUF: cheap local worker for edge/offline/fallback/compression tasks.
- EAGLE 3.1: serving-layer speculative decoding for speed.
- OSCAR: KV-cache compression for long-context memory economy.

Required gates:

- Every routing decision emits traceable evidence: requested capability, candidate models, route rationale, expected cost, fallback path, and quality estimate.
- Runtime accelerators cannot modify reasoning policy without explicit eval evidence.
- Quality regressions must trigger fallback and rollback.
- Long-context compression must preserve safety-critical and instruction-critical tokens.

### Knowledge and Ingestion Layer

LiteParse and the Knowledge Artifact Compiler belong together. LiteParse handles structured ingestion; KAC compiles repeated retrieval and parsing work into governed artifacts.

Candidate surfaces:

- `nexusnet/ingestion/liteparse_adapter.py`
- `nexusnet/knowledge/`
- `nexusnet/knowledge/artifact_compiler.py`
- `nexusnet/knowledge/request_contract.py`

Required gates:

- Preserve citations, permissions, source hashes, version, and transformation trace.
- Raw retrieval remains a fallback, not a discarded capability.
- Compiled artifacts must indicate freshness and invalidation conditions.
- Parser failures should become eval cases, not silent truncation.

### Behavioral Evaluation and Action Recovery

Petri/Bloom and AXPO should be treated as complementary. Petri/Bloom-style evaluation tests behavior. AXPO-style recovery repairs failed action/tool steps when reasoning was otherwise useful.

Candidate surfaces:

- `nexusnet/evals/behavioral/`
- `nexusnet/evals/petri_adapter.py`
- `nexusnet/policy/action_recovery.py`
- `nexusnet/trajectory/failure_dataset.py`

Required gates:

- Store failed trajectories with reasoning prefix, attempted action, observed failure, corrected action, and outcome.
- Evaluate action resampling separately from full trajectory resampling.
- Behavioral evals must run before promotion from shadow.
- Frozen and active upstreams need separate ledger treatment.

### Multimodal Teacher and Perception Lane

Keye-VL, Nemotron 3 Nano Omni, HF 2605.27365, and the MLLM self-improvement survey all point toward stronger multimodal perception and teacher supervision.

Recommended posture:

- Keep all as teacher, perception, or research candidates.
- Do not replace the core NexusNet brain or Mixtral plus Devstral fusion path without a new architecture branch.
- Use the MLLM self-improvement survey as process reinforcement: collect multimodal traces, organize them into datasets and memory artifacts, improve/adapt models, evaluate, and promote only with evidence.

Required gates:

- Multimodal benchmark set aligned to NexusNet tasks.
- Resource and hardware feasibility review.
- License and provenance review for every model or dataset.
- Teacher output must become reviewable curriculum/eval evidence, not opaque authority.

## Non-Assimilation Rules

- Do not switch NexusNet's core to any single external model, repo, paper, or agent framework based only on chat evidence.
- Do not claim an external project is integrated because its idea was discussed.
- Do not merge transcript claims and repository claims unless both sources have been inspected in the same evidence chain.
- Do not let a runtime optimizer, parser, or router become a cognition replacement.
- Do not promote a child model, skill, teacher, or runtime policy without sandbox, eval, rollback, observability, and governance evidence.

## Final Assimilation Thesis

The 17 chats converge on one pattern: NexusNet should assimilate external work as governed capability organs around its own gestational brain, not as replacements for that brain. The strongest opportunities are SkillOps, inference economy routing, action-step recovery, compiled knowledge artifacts, behavioral evaluation, and scratch apprentice training. Runtime optimizers, small local models, parsers, and multimodal teachers are valuable, but only when bound to NexusNet's existing evidence, promotion, rollback, and observability contracts.
